# Changelog

Versioned against magisterial developments — a new Vatican or USCCB statement touching AI, a revision to how a principle is interpreted — not against a sprint calendar. Every entry naming a change to `principles/` or `rubric/` links to its `docs/theological-review-log.md` entry.

## Unreleased

- **Added interaction auditing alongside use-case rating; renamed the skill to `rate-ai-against-cst`.** The assessment tool now takes either of two subjects through the identical two-stage rubric: a planned/described AI use (as before), or an actual `prompt` + `response` pair from a deployed LLM, audited after the fact — "is this specific response in line with CST," not just "is this use case." `eval/report.py` gained a `Subject` dataclass (`kind: "use_case" | "llm_interaction"`) that both the bright-line and graded rendering now key off of; `eval/assessment.py` validates that exactly one subject shape is given (never both, never neither, never `prompt` without `response`). `.claude/skills/rate-ai-use-against-cst/` renamed to `.claude/skills/rate-ai-against-cst/` and its `SKILL.md` now branches at the start between interviewing for a use case and collecting a verbatim prompt/response to audit — for an audit, both the bright-line check and the graded scores judge what the response actually said or did, not what the prompt asked for. `rubric/criteria.md` and the README updated accordingly.
- **Replaced the target/rater eval harness with a direct AI-use assessment tool.** The project's original shape — point a harness at a built AI system, run it through pre-written scenarios, score its responses via an LLM rater — didn't match what this project is actually for: rating a *described* AI use case against CST before or while it's built, the way a DPIA works. Removed `eval/harness.py`, `eval/loading.py`, `eval/scenario.py`, `eval/raters/` (and the `llm`/`anthropic` optional dependency it required), `rubric/scenarios/`, `integrations/ci-advisory-check.yml`, and `.claude/skills/run-cst-eval-harness/`. Added: `principles/non-negotiables.yaml` (a bright-line gate — direct abortion, euthanasia/assisted suicide, direct killing of the innocent — cited to Compendium §155 and Magnifica Humanitas §55, both verified against the primary text), `eval/principles.py` and `eval/assessment.py` (loads and validates a written assessment against real principle/non-negotiable ids; makes no LLM calls itself), a rewritten `eval/report.py`, and a project-local Claude Skill (interviews the user, does the CST judgment in conversation grounded directly in `principles/*.yaml`, then calls `eval.assessment` to validate and render — see the entry above for its current name and shape). `rubric/criteria.md` now documents the real two-stage rubric this implements — bright-line check first, then a graded 1-5 score with mitigations. **Unreviewed — beta**, including `non-negotiables.yaml`; see `docs/theological-review-log.md`.
- Added `.claude/skills/run-cst-eval-harness`, a project-local Claude Skill wrapping `eval.harness` so a non-technical user can get a real advisory report without hand-writing target/rater wiring — `scripts/setup_venv.sh` (robust Python 3.12+ venv setup), `scripts/scaffold_target.py` (writes demo or real target/rater boilerplate, with tests), and `references/` (writing a target, full CLI reference, how to read a report back in plain language). Lives under `.claude/skills/` rather than this repo's usual `skills/` convention so Claude Code actually discovers it. Validates cleanly with `skills-ref`. **Retired** — see the entry above.
- Added `principles/social-justice.yaml` as an eighth principle, cited to *Magnifica Humanitas* §77-81, which names "the principle of social justice" as one of its own five headline principles — not previously one of this project's seven. `preferential-option-for-the-poor.yaml` updated to cross-reference it. "Seven principles" updated to "eight" throughout README, CHECKLIST, and Definition of Done. Still **unreviewed** — beta. See `docs/magnifica-humanitas-findings.md`.
- All seven `principles/*.yaml` enhanced with *Magnifica Humanitas* citations alongside the existing Compendium ones (paragraph numbers verified directly against the primary text). Notable additions: `subsidiarity.yaml` now cites MH §71's explicit extension of subsidiarity to AI platforms; `universal-destination-of-goods.yaml` cites MH §67's explicit naming of algorithms, data, and digital platforms as goods the principle covers. See `docs/magnifica-humanitas-findings.md` for the full findings, including an open question about whether MH's "principle of social justice" (§77-81, not currently one of this project's seven) should become an eighth principle. Still **unreviewed** — beta.
