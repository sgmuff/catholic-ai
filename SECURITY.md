# Security Policy

## Reporting a vulnerability

If you find a security issue in any project in this repository — in the shared Skills, in a project's own code, or in the CI configuration — please report it privately rather than opening a public issue. Email sgmuff@proton.me with a description of the issue, the affected project or path, and, if possible, steps to reproduce it.

You should expect an acknowledgment within a few days. Once a fix is available, it will be disclosed alongside the affected project's next update; reporters are credited unless they ask not to be.

## Scope

This policy covers the repository's own code and configuration — dependency vulnerabilities, secrets exposure, insecure defaults in any bundled scripts, and issues in CI workflows. It does not cover the institutions that may later adopt work from this repository; their deployments are their own responsibility to secure.

## Baseline

The substantive security and privacy standard every project in this repository is held to — for its own engineering practice and for the governance work product it produces — is defined in [`docs/standards/security-and-privacy.md`](docs/standards/security-and-privacy.md).
